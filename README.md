# Board Game Collection

A small shared board-game shelf built with the Next.js App Router. The current milestone uses invented sample data held in TypeScript; it has no API, database, or persistent write actions.

## Architecture

```text
board-game-collection/
├── app/
│   ├── games/
│   │   ├── [slug]/
│   │   │   ├── error.tsx       Game-detail error boundary
│   │   │   ├── loading.tsx     Game-detail loading UI
│   │   │   └── page.tsx        Game details and play history
│   │   ├── new/
│   │   │   └── page.tsx        Add-game form UI
│   │   └── layout.tsx          Layout shared by /games routes
│   ├── sessions/
│   │   └── page.tsx            Global play log
│   ├── globals.css             Global styles
│   ├── layout.tsx              Root layout and site navigation
│   ├── not-found.tsx           Shared 404 page
│   └── page.tsx                Game shelf
├── components/
│   ├── game-shelf.tsx          Player-count and complexity filters
│   └── nav-link.tsx            Navigation link with active-page state
├── lib/
│   └── games.ts                Sample games, sessions, and data helpers
├── public/                     Static assets
│   ├── file.svg
│   ├── globe.svg
│   ├── next.svg
│   ├── vercel.svg
│   └── window.svg
├── .next/                      Generated by Next.js; not committed
├── node_modules/               Installed by npm ci; not committed
├── .gitignore
├── AGENTS.md
├── eslint.config.mjs
├── next-env.d.ts               Generated by Next.js
├── next.config.ts
├── package-lock.json
├── package.json
├── README.md
└── tsconfig.json
```

The root layout provides the site-wide navigation and page-title template. `NavLink` uses the current pathname to set `aria-current`. The games layout is shared by `/games/new` and `/games/[slug]`.

The game-detail route awaits its `slug`, loads the matching game, and creates a title from that game. `generateStaticParams` prerenders the known sample slugs; `dynamicParams = false` makes unknown slugs return a 404. The simulated one-second data lookup lets the detail route demonstrate its loading state in development.

## Routes

| URL | Page |
|---|---|
| `/` | Game shelf with game-count and play-count summaries, plus filters for player count and complexity |
| `/games/new` | Add-game form UI; saving is not implemented yet |
| `/games/[slug]` | A game's details and its play-session history |
| `/sessions` | All sample play sessions, newest first |

## Sample data

`lib/games.ts` defines the `BoardGame` and `PlaySession` types and exports the sample records. Each session's `gameSlug` matches a game's `slug`. To add a sample game, add it to `games`; add its sessions to `playSessions` using the same slug. Since known game pages are statically generated, rebuild after changing the game list.

## Requirements

- Node.js 20.9 or newer
- npm
- Git

Dependencies are pinned by `package-lock.json`. Use `npm ci` to install the locked versions.

## Clone and run

Replace `<owner>` and `<repository>` with the GitHub account and repository name. For a private repository, the GitHub account must have access.

```bash
git clone https://github.com/<owner>/<repository>.git
cd <repository> 'continue to cd until you reach board-game-collection'
npm ci
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Checks and production run

```bash
npm run lint
npm run build
npm start
```

`npm start` serves the production build and therefore must be run after `npm run build`. The known game-detail pages are prerendered during the build; the development server renders pages on requests and shows the simulated loading state.
